# 电商四模型设计

用户已确认使用 `ecommerce_dw` 真实数据，替换固定模拟订单与退款示例，不使用 seed；保留工程与 profile 名 `ecommerce_metrics`。

## 方案与边界

采用四个语义模型：`orders` 一行一条订单商品明细，`users` 一行一个用户，`products` 一行一个商品，`stores` 一行一家店铺。另一方案是一行一订单并增加第五个明细模型；用户选择四模型明细粒度方案，以支持商品分析而不放大订单金额。

`orders` 读取 `fact_order_items` 并关联唯一的 `fact_orders`，仅取得用户、店铺、日期、状态、渠道和支付方式；金额、折扣、数量均取明细，不复制订单总额和运费。三个维表分别读取 `dim_customer`、`dim_product`、`dim_store`。实体关联为 foreign → primary。

成交只认 `COMPLETED`。成交商品金额不含运费，排除取消、待支付、已退款订单；这是按当前订单状态计算的成交口径，不是支付流水或净现金收入。订单数、成交订单数和购买人数均去重，不得跨商品分组直接相加。商品分组下的客单价是该商品分组金额除以包含该分组商品的成交订单数。

## 指标与维度

- 订单：`order_count`、`completed_order_count`、`sales_amount`、`sales_quantity`、`buyer_count`、`average_order_value`；日期、订单号、状态、渠道、支付方式，以及三个维表的维度。
- 用户：`user_count`、`new_user_count`；用户编号、性别、年龄段、会员等级、省市、获客渠道、注册日期。不暴露姓名为默认分析维度。
- 商品：`product_count`、`active_product_count`；SKU、商品名、一二级类目、品牌、上架日期、在售状态。
- 店铺：`store_count`、`new_store_count`；店铺编号、名称、类型、省市、开店日期。

用户、商品、店铺是当前快照，不伪装成历史快照。总数无时间筛选时统计全部；按默认聚合时间筛选时分别表示注册、上架、开店日期范围内的数量。新增用户数/新开店铺数按注册/开店日期统计，和对应总数共享计数表达式。零成交分组的客单价为 NULL。

## 数据与验证

时间骨架按四模型的最小、最大业务日期生成连续自然日，作为第五个物理模型但不启用语义模型。源日期表不足以覆盖 2019 年注册和开店数据。使用 StarRocks `generate_series` 动态生成偏移，无 seed，也不生成业务数据。

只读 `ecommerce_dw`，模型构建到独立目标 schema；不改源表，不删除历史部署表，不推送或发布。当前目录开发；本计划完成后按工作区约定提交一次。

验证覆盖 source 主键/外键、模型行粒度与空值、逐单金额与数量对账、连续日期覆盖、恰好四个语义模型和十二个指标、MetricFlow 全量及多维查询与源 SQL 对账、非成交分组零值与比率 NULL、2019 年新增用户查询。
