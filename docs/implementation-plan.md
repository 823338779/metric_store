# 电商 dbt 初始化计划

目标：5 张核心业务表（用户、店铺、商品、订单、订单明细），2020-01-01 至 2027-12-31 共 2,922 天，日订单 100—300 笔。用户确认本地 DuckDB 和数百万行规模。

架构：Python + DuckDB 集合 SQL 生成 raw 源表；dbt Core 1.11 管理 staging、维度、事实、汇总和语义层。支付、退款直接记录在订单上；不增加其他核心业务表。固定种子、锁定依赖，保证分批等价和幂等。模拟金额为 CNY，交易生命周期在当日结束。

1. 数据生成：先测试 5 表范围、闰日、末日、日覆盖、金额及商品归属、分批等价和重跑幂等，再实现生成器。
2. dbt 建模：5 个 source、5 个 staging、用户/商品/店铺/日期维度、2 个增量事实表、4 个汇总表和指标定义。
3. 验证：完整 dbt build；隔离数据库上对比逐日追加、重跑、历史回补和全量构建；文档与行数报告。

边界：订单金额等于明细净额之和；退款不大于支付；用户先注册再下单；同一订单仅含所属店铺商品；初始 example 保留并禁用；不改动已有 .idea 文件。

数据生成仅按指定日期替换订单和明细，引用用用户全集与静态店铺/商品幂等初始化。事实表默认重算最近日期并追加新日；历史修改通过 backfill_start 显式回补。维度和汇总重建。此方案不模拟 CDC 删除或跨日支付退款。
